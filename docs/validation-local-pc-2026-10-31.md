# DiskScope 0.3.3 local-PC qualification follow-up

This follow-up uses the user's existing Windows 11 Pro x64 build 26300 PC.
It is an unpublished qualification build. Main and published 0.3.2 remain
unchanged. Exact source, compiler and binary identities are retained in each
candidate's BUILD_PROVENANCE.json and qualification evidence; observations from
different binaries are not silently combined into an exact-artifact claim.

## Defects reproduced and fixed

Native desktop testing found that F1 Help followed by Tab focused the background
Overview control. Transient windows recorded their invoker but neither initialized
nor contained keyboard focus. They now initialize focus, contain Tab/Shift-Tab,
disable background activation/shortcuts, and restore the invoker after Escape or
the title close control. Opening export also blocks file-action shortcuts in its
first frame. Existing destructive confirmation semantics remain enforced.

Native table traversal exposed anonymous focusable header/body cells generated by
the table builder. These headers are static labels, not sorting controls. Static
cells no longer create false focus stops; named row controls retain pointer and
keyboard selection/navigation and visible focus. Column splitters have descriptive
names, visible focus, range information and bounded Left/Right resizing in
16-point steps. This uses public table widths/initial/reset APIs, preserving
pointer dragging and responsive viewport resets without a dependency fork.

Actual application-frame regressions failed before each corresponding fix and
passed afterward. Tests cover opening-frame background activation, first focus,
forward/reverse containment, nested dialogs, Escape/title-close restoration,
row selection, all column splitter bounds, viewport reset and pointer resizing.
Independent read-only review found no actionable regression in the final diff.
Fresh local default tests: 482 passed / 15 ignored; diagnostics: 485 passed /
15 ignored. Final headless, lint, packaging, hosted and new-binary desktop results
are recorded separately rather than inferred from this description.

The intermediate source `0c9b01e` passed hosted tests but was rejected after a
native crash: Settings -> 150% text -> Escape exited with code 101 because an
AccessKit focused ID was absent from the node list. Its stderr/exit record is
retained in research/local-pc-desktop/compact-exit-repro/ and its package directory
is marked DO NOT DEPLOY. A removed sidebar or popup child could be restored as
focus. The follow-up proves the invoker exists in the current render, uses the
stable compact menu parent, and safely falls back to root when the target is gone.
The exact sequence and intermediate frames now pass the same AccessKit Consumer
tree validation used by Windows. This adds only a test dependency already locked
transitively, without changing production dependencies.

Native 150% testing also found clipped Settings content and export feedback hidden
behind the modal. All seven transient dialogs now use viewport bounds, vertical
scrolling and keyboard/focus reveal at actual native display scaling plus app
zoom. Export success/failure is an enabled polite status inside its dialog, and
busy Save retains focus while a separate callback guard prevents duplicate work.
Private sessions start maximized within Windows' work area so their initial
cascaded window does not hide bottom controls. Ordinary saved placement remains
unchanged. Accept these fixes only with corresponding exact-binary native test
records; this implementation description alone does not establish a native pass.

## External and environment limits

An approved signing certificate is still unavailable. The current executable and
installer remain unsigned; hashes do not establish approved publisher identity.
Malwarebytes is registered on this host; Defender reports Not running. Neither a
registered product nor successful app launch is an actual EDR compatibility scan.
No security service, protection policy, trust store or exclusion was changed.

Narrator was started for testing, but access to its first-run ShellHost window
timed out at the computer-control approval prompt. Native app accessibility-tree
observations and keyboard tests do not establish spoken feedback correctness.
Narrator was exited using its documented keyboard shortcut, preserving startup
and privacy configuration; no spoken-completion pass is invented.

The approved DD-Lab-Target1 VM cannot boot or be cloned because its configured OS
disk is absent. release.vhdx is an auxiliary data disk, not an OS source. A complete
Windows 11 Pro build 26100 source exists at DD-Lab-Parity-Ref; an independent,
network-disconnected clone requires the user's alternate-source authorization.
No original VM/disk was changed. VM evidence is retained in research/local-pc-vm/.

Real client token/UAC cases, hardware/providers, constrained memory/disk classes,
actual ScreenConnect, full Narrator/DPI trials, approved publisher/EDR acceptance
and independent technician task trials remain separate qualification gates. Their
status must change only from observed evidence, never from repeated unit tests or
an arbitrary numerical grade. Use the existing helpdesk checklist and runbook.
